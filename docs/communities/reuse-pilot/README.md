# Can a second builder use the method?

A proposed first creation-cell experiment for Community OS issue #66. The existing [operating model](../starlight-communities-operating-system.md) owns cells, quests, artifacts and reflection. This packet tests one missing property, independent transfer of a method. It is a local research instrument. Hosted event ingestion, scoring member competence, publication and commerce need their respective owners.

## Member experience

A member opens one quest with an example deliverable and a visible time allowance. They work privately, submit an exact artifact revision for peer review and choose whether the group may see an example. The reviewer returns one acceptance decision and one concrete correction. A different member takes the method to a new brief. A clean fork carries its author, version, rubric and license once confirmed. No client intake, private manuscripts, keys or conversation history travel with it.

FrankX is the first proposed quest. A builder delivers a one-page model routing decision a client could hand to an implementer. The author provides the method, one independent builder runs it, and a third person judges the outputs. A four-person cell can rotate roles. One person acting through several accounts does not supply independent evidence.

## Two comparable briefs

Give both arms the same vendor excerpts on provider keys and retention, plus a fictional deployment sheet explicitly missing fallback-region evidence. Brief North is a support assistant with customer-funded inference, zero retention and EU-only processing. Brief South is a document assistant with the same three obligations. Give each brief a different client context and output identifier. The deliverable for both is a routing recommendation, cited basis, evidence gap and smallest staging test. Shuffle brief-to-arm assignment and rotate which arm goes first across builders. Record assignment and actual order before review. Carryover in a small cell still limits causal claims.

- Baseline arm: the builder's usual assistant and the source packet.
- Method arm: the same assistant and packet, plus the pinned FrankX method and its read-only review tool.
- Reviewer: present both outputs in random order with arm and model labels removed. Accept only when the output identifies payer fallback, retention eligibility and missing region proof, gives an actionable check for each, and avoids declaring production approval. Retain disagreement or rejection with the builder's permission.
- Cap each arm at 20 minutes and the same preapproved inference allowance. Record abandonment at the cap. Record founder intervention even when it saves a stalled attempt. Retain model, prompt, tool and source versions plus actual cost in the private run record when available.
- Treat a plausible answer with a false regional assurance as a critical failure. Pause distribution and add the failure to the regression suite. Record withdrawal of a contribution against the actual shared copy and available access controls before further use.

## Decision and ownership

Frank owns pilot recruitment, participant consent, the definition of an acceptable output and the commercial decision. The implementation agent pins artifacts, prepares blinded pairs and tracks defects. Another member evaluates the actual artifact in context. An agent can flag missing evidence. A person decides whether the result is usable. Explicit permission and rights review precede a public lesson, remix or commercial edition.

A first independent success licenses a second pilot, not a general rollout. Repeat with a different builder and brief before investing in community distribution. Compare paired discordant outcomes, time conditional on both outputs being accepted, failures and founder interventions. At this sample size report counts. Expand managed capacity only when repeat demand, attributable cost and fulfillment evidence justify it.

## Run the local scorecard

From this directory run:

```sh
node --test score.test.mjs
node score.mjs example.json
```

The example uses synthetic aliases and digests, and its time difference is illustrative. For an actual study, keep the packet in a private operator workspace, compute SHA-256 from the exact method and submitted/reviewed bytes, and use pilot-local opaque aliases. Never commit participant packets. Store consent, role verification, evidence access and withdrawals in the existing authorized system. The scorer validates record shape and equality of supplied digests. It cannot establish identity, consent, truth of a review or which tool was actually used. Start a new packet whenever the method revision changes. Record all assigned pairs including abandonment; incomplete enrollment belongs in the pilot log. No timing or economics should be imputed for missing observations.

The program emits aggregate counts only. Paired acceptances require a reviewed artifact and no founder rescue. Rejections and abandoned arms remain in the denominator. Negative paired time savings are retained. A zero denominator yields null.
